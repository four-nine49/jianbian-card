# 开局框架 · SillyTavern 扩展（窗口 + 悬浮窗版）

> 按《酒馆扩展窗口悬浮窗编写指南》整体重写的原生 SillyTavern 扩展。
> 旧版（`开局框架-归档`）以"酒馆助手引导加载器注入主页面"方式运行，卡在 bundle 顶层崩溃；
> 本版改为 **manifest.json 声明的标准扩展**，由酒馆直接把 `dist/index.js` / `dist/index.css`
> 注入主页面，从结构上消除了那类问题。

## 功能

- **数据表格**：聊天级表格存储（chat 变量，随聊天文件持久化），zod 校验，可视化 CRUD
- **AI 填表**：`generateRaw` + `custom_api`（独立模型/温度）+ `json_schema` 强制 strict JSON；
  单表粒度：读取对话轮数 / 填表频率 / 标签过滤 / **填表分组**，自动 + 手动调度
- **AI 对话引导**：七步开局引导（规则表随 bundle 打包），generateRaw 完全自控上下文，
  结算块解析 → 校验 → 自动落地为表格初始数据
- **窗口**：可拖拽（标题栏）、可缩放（右/下/斜角手柄）、可开关，位置尺寸持久化
- **悬浮按钮**：🎬 圆钮，拖拽移动 / 点击开关窗口（5px + 300ms 阈值区分），位置持久化、可隐藏
- **Slash 命令**：`/opening`（别名 `/开局`）开关窗口

### 规则包格式（导入用 JSON）

```json
{
  "id": "my-card",                       // 必填，唯一标识；同 id 再次导入 = 覆盖
  "name": "我的卡片",                     // 必填，显示名
  "description": "一句话说明",
  "rulesText": "给 AI 的规则全文……",       // 引导对话的 system 注入；留空则无法开始引导
  "settlementStartMark": "【自定义开局结算开始】",   // 结算块开始标记（可省，用默认）
  "settlementEndMark": "【自定义开局结算结束】",     // 结算块结束标记（可省）
  "requiredKeys": ["模式", "点数"],        // 结算块必填键（可省 = 不校验）
  "tables": [                             // 结算落地用哪些表
    { "uid": "t1", "name": "物品栏",
      "purpose": "这张表是干嘛的（给人看的注释）",
      "scope": "always",                  // always=开局必建；onSeed=结算有初始行才建
      "headers": ["名称", "数量"],
      "sourceData": { "note": "列定义（发给 AI）", "insertRule": "…", "updateRule": "…", "deleteRule": "…" },
      "updateConfig": { "enabled": true, "contextRounds": 3, "updateFrequency": 1, "group": "" } }
  ],
  "seedRows": {                           // 静态初始行：表 uid -> 行数组（可省）
    "t1": [["初始物品", "1"]]
  }
}
```

说明：`seedRows` 是"开局就写死"的行；内置开局包额外带**动态种子**（从结算块字段算出
主角/技能/资产等行），这一能力目前仅代码内置包可用——导入包想完全复刻请把映射逻辑
写进 `builtin-packages.ts`（照抄 `CUSTOM_OPENING_PACKAGE` 的 `seedDynamic` 写法）。

  发送失败会自动回滚玩家消息，不会留下半截对话。
- **引导对话 API 可选**：设置页新增「引导对话 API」——默认跟随酒馆当前 API，
  也可切「自定义」填独立的代理预设/URL/Key/模型/温度（与填表 API 相互独立），保存即生效。
- **提取标签给具体示例**：正文被 `<content>…</content>` 这类标签包着时，
  提取标签填 `<content>|</content>` 即可（自动取文中最后一对，多对规则每行一条）。
- **（v1.2.1）填表 API 也可选模式**：和引导对话一样，可选「跟随酒馆当前 API」或「自定义」；
  切走时已填的自定义配置保留，切回来还在。填表默认仍为自定义（老配置不受影响），
  引导对话默认跟随酒馆。

## v1.1 更新

- **对话按「轮」读取**：`读取对话轮数` 取代原楼层数。1 轮 = 用户发送 + AI 回复，
  末尾还没接上用户回复的连续 AI 回复也算进最新一轮。全局默认 + 单表可各自设置。
- **填表分组**：每张表可设 `填表分组`（组名）。同组名的表合并成**一次** API 请求由同一个 AI 一起填；
  不同组名（含默认组）各自单独发一次请求——重要/复杂的表单独起组名即可隔离。
  组内读取轮数/跳楼数取成员最大值。
- **提示词模板段可增删**：段支持添加、删除、上下移动、ON/OFF，不再固定 8 段。
- **占位符全部带中文说明**：提示词模板页内置占位符表格，说明每个 `{{xxx}}` 替换成什么。
- **界面全面中文化**：设置页 / 表配置页每个字段都有中文标签 + 下方灰色小字解释；
  去掉了从未启用的 `batchSize` 参数。

> 从 v1.0 升级：旧聊天里已存的表配置会自动迁移到默认值（读取 3 轮、默认组），
> 在「表结构/配置」页按需重新设置即可。

## 两种发行形态（照抄玉子手机）

一套源码、一份 `dist/` 产物，两种加载通道：

| 形态 | 加载方式 | 更新 |
|---|---|---|
| **扩展版** | 把整个目录放进 `SillyTavern/public/scripts/extensions/third-party/`，扩展管理器经 `manifest.json` 加载 dist | 手动（或仓库开 auto_update） |
| **酒馆助手版** | 把 `酒馆助手脚本-开局.json` 导入酒馆助手并启用，加载器每次从 jsdelivr CDN 拉取**同一份 dist 产物**注入主页面 | **自动**（GitHub API 查最新 tag） |

两版**运行时互斥**：bundle 会在主页面 window 上设 `__OPENING_FRAMEWORK_INSTANCE__`，
脚本版加载器检测到它就弹窗阻止——和玉子一样，**请勿同时启用扩展版和脚本版**。

### 发布脚本版（一次性）

脚本版加载器从 CDN 拉代码，所以需要先把项目发布到 GitHub：

1. 把 `开局框架-扩展/` 推到 GitHub 仓库（**dist/ 一起提交**，CDN 靠它）
2. 打版本 tag：`git tag v1.0.0 && git push --tags`（tag 必须是 `v<manifest.version>` 格式）
3. 改 `package-loader.mjs` 顶部的 `REPO_OWNER` / `REPO_NAME` 为实际仓库
4. 运行 `node package-loader.mjs` 重新生成 `酒馆助手脚本-开局.json`（自带 23 项契约自检，
   对照玉子 `check-script-loader-contract.cjs`：实例 key 与 bundle 一致、tags API 回退、
   注入 id 稳定、查重顺序、不顶层 return、不自动 destroy 等）
5. 把 json 导入酒馆助手，启用即可

以后更新：改代码 → `node build.mjs` → 提交并打新 tag → 两个版都自动/手动更新，加载器无需重新生成（除非换仓库）。

### 安装扩展版

把整个 `开局框架-扩展/` 目录复制到
`SillyTavern/public/scripts/extensions/third-party/` 下（或通过扩展管理器从 git URL 安装），
在扩展面板启用即可。**依赖酒馆助手（TavernHelper）扩展**（manifest `requires` 已声明）——
未启用时窗口/面板仍可打开，但变量与生成功能不可用。

## 设置持久化（指南 五）

全部设置存 `getContext().extensionSettings['opening-framework']`，经 `saveSettingsDebounced()`
防抖落盘，zod 校验兜底：

| 键 | 说明 |
|---|---|
| `windowX/Y/Width/Height` | 窗口位置与尺寸（拖拽/缩放结束持久化） |
| `toggleX/Y/Size` | 悬浮按钮位置与尺寸 |
| `floatingToggleEnabled` | 是否显示悬浮按钮（设置页可切） |
| `autoFillEnabled` / `maxRetries` | 自动填表开关 / 失败重试次数 |
| `fillApi` | 填表独立 API（proxyPreset/apiUrl/key/model/temperature/…） |
| `globalDefaults` | 单表未配置时的填表默认值 |
| `promptTemplate` | 填表提示词模板（占位符段，设置页可编辑） |

聊天级数据（表格 `__of_tables__`、引导对话状态 `__of_dialogue__`）仍走 TavernHelper 的
**chat 变量**，随聊天文件持久化、按聊天天然隔离。

## 与归档版的关键差异

| 项 | 归档版 | 本版 |
|---|---|---|
| 运行形态 | 酒馆助手引导加载器注入 IIFE（卡顶层崩溃） | manifest 标准扩展，酒馆 import() 加载 ESM |
| 窗口 | 固定 right/bottom 面板，不可拖拽缩放 | 可拖拽/可缩放/可开关，位置持久化（指南 三） |
| 悬浮按钮 | 单纯 click，不可移动 | 拖拽/点击区分（5px+300ms），位置持久化（指南 四） |
| 业务设置 | TavernHelper script 变量（扩展环境无 script_id，不可靠） | extensionSettings + saveSettingsDebounced |
| zod | 依赖全局 `z` | 显式 import，打进 bundle |
| 模块顶层读全局 API | 有（崩溃根源） | 无——页面直接 import 模块函数 |
| 样式 | 运行时注入 `<style>` | dist/index.css 由 manifest 注入 |
| 生命周期 | destroy 残缺、监听器分散 | EventManager 统一登记，destroy 全量清理 |
| 切聊天时 | `resetDialogue()` 会清掉新聊天的引导进度（隐患） | 只重置内存楼层计数；对话状态按聊天隔离保留 |
| Slash 命令 | 无 | `/opening` / `/开局`，动态 import 失败仅降级 |
| z-index | 99999/99998（盖过酒馆全屏 UI） | 窗口 9999、悬浮窗 10000（指南 八分层） |
| 表模板导入 | `import('?raw')` 动态 + 无校验 | 静态 raw 打包 + `TableDef` zod 校验（坏模板跳过并告警） |
