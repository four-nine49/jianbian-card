## 1. 过载率 / 过载风险 需求规格（人读版）

主角的相关状态（输入）：

| 字段 | 含义 | 单位 |
|---|---|---|
| `能量kJ.当前` / `能量kJ.上限` | 当前/上限能量储量 | kJ |
| `精神点.当前` / `精神点.上限`（记作 `mCur` / `mMax`） | 当前/上限精神力 | 点 |
| `爆发线kW`（记作 `burst`） | 瞬时输出功率上限 | kW |
| `持续线kW`（记作 `sus`） | 持续输出功率上限 | kW |
| `身体状态` | 正常 / 轻伤 / 重伤 / 过载透支 | 枚举 |

主角默认：能量 5000/10000 kJ，精神 80/90，爆发线 300 kW，持续线 50 kW。

### 指标一：过载率（无上限，保留 1 位小数）

```
过载率 R = power / 基准线 × 100%
基准线 = 作用时长 relT >= 1 秒 ? 持续线(sus) : 爆发线(burst)      （防零：max(1, 基准线)）
```

- 短脉冲（<1s）比爆发线；长脉冲（≥1s）比持续线。
- 无上限（可远超 100%）。

### 指标二：过载风险（0–100%，取整）

```
过载风险 = clamp( 0, 100, round( Φ_power + Φ_barrier + Φ_body ) )
```

- **模块 A 瞬时功率冲击** `Φ_power = f(R) × β × γ`
- **模块 B 认知壁垒反噬** `Φ_barrier = (亲和罚 + 陌生罚) × β × Ω(P)`
- **模块 C 生理与条款硬性代价** `Φ_body = Σchip.w + sev×5 + (exhaust?20:0)`（不受心智上限抵消）

### 精神状态因子

```
β = (100 / max(1, mMax))^0.5        // 精神上限底蕴系数（100 标准=1，300≈0.58）
P = clamp(0, 1, mCur / max(1, mMax)) // 当前精神比例
γ = 0.8 + (1 - P) × 1.2              // 疲劳系数 0.8 ~ 2.0（线性）
Ω = 0.6 + 1.4 × (1 - P)^2            // 认知精力压制曲线 0.6 ~ 2.0（非线性）
```

### 各模块分项展开

**f(R) 分段功率映射：**

| 过载率 R | f(R) |
|---|---|
| R ≤ 80% | `0`（安全区） |
| 80% < R ≤ 100% | `(R − 80) × 0.25` |
| 100% < R ≤ 150% | `5 + (R − 100) × 0.6` |
| R > 150% | `35 + (R − 150) × 1.0` |

**D_affinity（亲和门控罚）：**

| 门控 | 罚 |
|---|---|
| 主分支 main | 0 |
| 次族/同族 mid/次 | 6 |
| 全陌 far | 18 |

**陌生罚**：`(max(1, unf) − 1) × 20`

**Φ_body 硬性代价：**

```
Σchip.w：特殊风险条款权重总和（calcCircuit 各族 push 的 chips）
sev×5：伤势（正常0 / 轻伤1 / 重伤2 / 过载透支3）
exhaust?20:0：储量透支（bill > 能量当前）
```

## 2. 过载率 / 过载风险 三模块公式（纯数学版）

```
过载率 = power / 基准线(relT>=1 ? sus : burst) × 100%      [无上限, 1位小数]
过载风险 = clamp[0,100]( round( Φ_power + Φ_barrier + Φ_body ) )

Φ_power   = f(R) × β × γ
Φ_barrier = (D_affinity + (max(1,unf)-1)×20) × β × Ω(P)
Φ_body    = Σ chip.w + sev×5 + (exhaust ? 20 : 0)

f(R)：R≤80→0；80<R≤100→(R-80)×0.25；100<R≤150→5+(R-100)×0.6；R>150→35+(R-150)×1.0
D_affinity：main→0；mid→6；far→18
β = (100/max(1,mMax))^0.5
γ = 0.8 + (1-P)×1.2
Ω = 0.6 + 1.4×(1-P)^2
P = clamp(0,1, mCur/max(1,mMax))
sev：正常0/轻伤1/重伤2/过载透支3
```

## 3. 引擎输入/输出格式

### 核心入口 `quote(req, ctx)`

```js
const q = E.quote(req, ctx);
```

**`req`（一次施法请求）**

```js
{
  fam: 'pour' | 'flow' | 'struct' | 'life' | 'perce',  // 族 id
  e: 0~100,           // E 滑杆（注入能量）；flow 系忽略（E 由公式导出）
  c: { ... }          // 参数向量（该族的参数键值，见代码 FAMS 定义）
}
```

**`ctx`（上下文，全部由宿主从存档拼好传入）**

```js
{
  aff: {
    main: [ { fam: '倾泻', br: '光' }, ... ],   // 主分支数组（fam 是中文族名，br 是分支名）
    subs: [ { fam: '波动', br: '媒介波' }, ... ] // 次分支数组
  },
  scene: {
    wind: 40,      // 风力档：0/40/70/95
    mat: 3000,     // 可塑无机物 kJ：0/3000/20000
    water: false   // 水体在场
  },
  char: {
    burstKW: 300,      // 爆发线（瞬时功率上限）kW
    sustainKW: 50,     // 持续线（持续功率上限）kW
    speed: 1,          // 施法速度倍率（默认 1）
    eCur: 5000,        // 能量当前 kJ
    mCur: 80,          // 精神当前
    mMax: 90,          // 精神上限
    body: '正常'       // '正常' | '轻伤' | '重伤' | '过载透支'
  },
  tuned: [             // 已装槽且带微调预算的固定回路（微调对表）
    { id: 'fx-01', 名: '风切·标准发', params: {...}, budget: { br_min: 85, fv_max: 72, E_min: 1, E_max: 9 } }
  ]
}
```

注意：
- `aff.main[].fam` 是中文族名（倾泻/波动/结构/生机/感知），`br` 是分支名（见 `TREE`）。
- `char.body` 影响伤势上浮：正常0/轻伤1/重伤2/过载透支3 → 精神倍率 `1+0.25×sev`、能量倍率 `1+0.15×sev`。

### `quote` 返回值

```js
{
  E_out: 数字,     // 输出能量 kJ
  bill: 数字,      // 能量账单 kJ（回合末从储量扣，含伤势能量倍率）
  mind: 数字,      // 精神消耗（含亲和/陌生/伤势/微调）
  relT: 数字,      // 作用时长 s
  readyT: 数字,    // 导引耗时 s
  power: 数字,     // 瞬时功率 kW = bill / relT
  tell: 数字,      // 征状等级 1~5
  risk: 数字,      // ★ 过载风险 0~100（取整）
  overloadRate: 数字, // ★ 过载率 %（无上限，保留1位小数）
  zone: { n: '绿·轻度', c: 'g' },  // 精神负荷区
  beta: 数字,      // 精神上限系数
  gamma: 数字,     // 疲劳系数
  unf: { d: 数字, unf: 数字, parts: [...] },  // 陌生系数
  chips: [ { t: '文本', w: 权重, l: 'r|o|y' } ],  // 风险条款
  exhaust: bool,   // 储量透支（bill > 能量当前）
  overBurst: bool, // 功率超爆发线
  overSustain: bool, // 功率超持续线
  tunedHit: id|null, tunedName: 名|null,  // 微调命中
  r: { ... }       // calcCircuit 原始结果（out/bill/mind/relT/tell/branch/g/entity/effect/lines/chips 等）
}
```

## 5. 五族定位

| 族 | 定位 | 关键机制 |
|---|---|---|
| 倾泻 pour | 瞬时高能直线 | E 滑杆→输出；脉宽→功率；发散角→穿甲/面杀伤 |
| 波动 flow | 波与场，借力省耗 | 插槽=物理量，E 由公式导出；媒介波有"介质借用率"折价 |
| 结构 struct | 分子重排，不可逆 | 体量/基底/晶格/应力，账单=max(输出, 需求) |
| 生机 life | 催化剂不是锤子 | 对象/渗透/增殖/剂型/选择性，账单=输出×(1+0.4×渗透) |
| 感知 perce | 只读不写 | 精神是主账单，能量折算≤0.5kJ |

## 6. 引擎完整代码

- **常量/滑杆工具**：`WINDS/MATS/ANCH`（锚点分级）、`logv/sliderToKJ/pwS/massKg`（对数滑杆）、`TUNE`（可调参数）。
- **亲和门控**：`TREE/FAMKEY/tierOf/gateOf`（主×1/次×2/陌×4）。
- **波动系实体插槽**：`MODES/SUBS/SUBKEYS/curKey`。
- **五族参数定义**：`FAMS`（每族 ctrls）。
- **五族核算**：`calcCircuit`（核心公式库，倾泻/波动/结构/生机/感知）。
- **陌生系数**：`unfOf`。
- **微调对表**：`findTuned`。
- **伤势上浮**：`injuryMod`。
- **总装报价（过载率/过载风险）**：`quote`（三模块公式）。
- **编译出手单/待扣单**：`compileOrder/buildCastOut/makePending`。

```javascript
    const c = {}; for (const ctl of FAMS[fam].ctrls) c[ctl.k] = ctl.def;
    return syncParams(fam, c);
  }
  function syncParams(fam, cIn) {
    if (fam !== 'flow') return Object.assign({}, cIn);
    const c = Object.assign({}, cIn);
    for (const ctl of (SUBS[curKey(c)] || { ctrls: [] }).ctrls) if (!(ctl.k in c)) c[ctl.k] = ctl.def;
    return c;
  }

  function branchOf(fam, c) {
    if (fam === 'pour') return ['光', '电', '热'][c.phase];
    if (fam === 'flow') { const k = curKey(c);
      if (k[0] === '0') return '实体波';
      if (k[0] === '1') return '媒介波';
      return { '2-0': '电磁场', '2-1': '引力场', '2-2': '核力场' }[k];
    }
    if (fam === 'struct') return ['金属', '土石', '土石'][c.base];
    if (fam === 'life') return ['植物', '动物(含人体)', '微生物'][c.targ];
    return ['读心干扰', '信息伪造', '信息伪造'][c.pert];
  }

  function readableParams(fam, c) {
    const cc = syncParams(fam, c);
    const out = {};
    const put = ctl => {
      if (ctl.show && !ctl.show(cc)) return;
      const v = cc[ctl.k];
      if (ctl.type === 'seg') out[ctl.label] = (ctl.opts && ctl.opts[v] != null) ? ctl.opts[v] : String(v);
      else out[ctl.label] = ctl.fmt ? ctl.fmt(v) : String(v);
    };
    for (const ctl of FAMS[fam].ctrls) {
      if (ctl.k === 'sub') { out[ctl.label] = (SUBS[curKey(cc)] || {}).n || String(cc.sub); continue; }
      put(ctl);
    }
    if (fam === 'flow') for (const ctl of (SUBS[curKey(cc)] || { ctrls: [] }).ctrls) put(ctl);
    return out;
  }
```

```js
    uses: 数值|null, 来源, 审核存档: {...}|null
  } ],
  槽位: { 固定槽: [id|null×10], 自由槽: [id|null×3] },
  待扣单: [ { ref, 名称, bill, mind, tell, risk, 锚点, order, famKey } ],
  场景: { 风力档, 可塑无机物kJ, 水体在场 },
  感情追踪: { 角色名: {字段:值} }              // 旧字段，标准AI已改走表格（见 §5）
}
```

### 1.2 快照（状态栏快速读取，可选）

```js
function readSnapshot() {
  // 从最近几楼 stat_data.渐变带 读快照（比 chat 变量轻，但可能滞后一轮）
  var v = getVariables({ type: 'message', message_id: getLastMessageId() });
  return v && v.stat_data && v.stat_data['渐变带'];
}
```

### 1.3 写回（玩家操作后必须走这个，否则不落盘）

```js
function writeGame(mut) {
  updateVariablesWith(function (v) {
    var g = v['渐变带'];
    if (g) mut(g);                 // mut 里改 g 的字段
    return v;
  }, { type: 'chat' });
  // 300ms 后同步快照到最新楼（让其它界面也读到）
  setTimeout(function () {
    var g = readChat(); if (!g) return;
    var snap = JSON.parse(JSON.stringify(g));
    if (snap['主角']) delete snap['主角']['上次结算min'];
    updateVariablesWith(function (v) {
      v.stat_data = v.stat_data || {};
      v.stat_data['渐变带'] = snap;
      return v;
    }, { type: 'message', message_id: getLastMessageId() });
  }, 300);
}
```

**铁律**：玩家任何操作（施放/装槽/使用补给/调场景/确认手操）都要走 `writeGame` 改 `g`，然后 `render()` 刷新 UI。不改 writeGame = 数据丢失。

## 2. 引擎怎么用（`E = window.CircuitEngine`）

HTML 头部已内联引擎源码（`/*@ENGINE@*/` 被替换），直接 `var E = window.CircuitEngine || globalThis.CircuitEngine;` 即可用。

### 2.1 核心函数（状态栏会用到的）

| 函数 | 作用 |
|---|---|
| `E.quote({fam, e, c}, ctx)` | **核算施法**：返回 `{ bill(能量账单kJ), mind(精神), tell(征状), risk(过载%), E_out, power, zone, tunedHit, chips, r:{lines} }` |
| `E.initParams(famKey)` | 初始化一族参数的默认向量 |
| `E.syncParams(famKey, c)` | 参数向量同步/规范化 |
| `E.branchOf(famKey, c)` | 参数 → 分支 |
| `E.curKey(famKey)` | 当前族键 |
| `E.anchorOf(E_out)` | 能量输出 → 锚点名（如"微光/轰鸣"）|
| `E.compileOrder(q)` | 施法顺序文本 |
| `E.readableParams(famKey, c)` | 参数 → 中文可读 |
| `E.readableBudget(famKey, c, E_out)` | 微调预算 → 中文可读 |
| `E.budgetFrom(famKey, c, E_out)` | 预算对象 |
| `E.sliderToKJ / E.kjToSlider` | 滑杆 kJ 互转 |
| 常量 | `E.WINDS`(风力档) `E.MATS`(基底) `E.SUBS`/`E.SUBKEYS`(子键) `E.FAMS`(族) |

### 2.2 ctx（quote 的环境参数，必须传）

```js
var ctx = {
  aff: affinityOf(g),          // 亲和（五族亲和值；参考 statusbar 的 affinityOf）
  scene: { wind: g.场景.风力档, mat: g.场景.可塑无机物kJ, water: g.场景.水体在场 },
  char: { burstKW: g.主角.爆发线kW, sustainKW: g.主角.持续线kW, speed: 1,
          eCur: g.主角.能量kJ.当前, mCur: g.主角.精神点.当前, mMax: g.主角.精神点.上限,
          body: g.主角.身体状态 },
  tuned: tunedList(g)          // 已装槽且带预算的固定回路列表（参考 statusbar 的 tunedList）
};
```

### 2.3 施放回路（挂待扣单给 AI 结算，参考 statusbar 的 doCast）

```js
var q = E.quote({ fam: c.famKey, e: c.注册e || 0, c: c.参数向量 }, ctx);
g.待扣单.push({
  ref: c.id, 名称: c.名称,
  bill: q.bill, mind: q.mind, tell: q.tell, risk: q.risk,
  锚点: E.anchorOf(q.E_out), order: E.compileOrder(q), famKey: c.famKey
```

## 4. 手操（操作表）—— 新增 tab 的接口

- 存储：chat 变量 `渐变带.操作表` = `{ manual: true/false, circuits: [id], counts: [n] }`
- 状态栏「手操」tab：勾选回路 + 次数 → 实时 `writeGame` 存操作表；「确认操作」按钮：
  1. 读操作表
  2. 对每个回路 `E.quote` 算费，累加 totalBill/totalMind
  3. **只扣** `g.主角.能量kJ.当前 -= totalBill`、`g.主角.精神点.当前 -= totalMind`（**不挂待扣单**——手操当场结清）
  4. 清空操作表 `{manual:false, circuits:[], counts:[]}`
- 每轮自动清空（扩展侧 runTurn 开头 clearOps；状态栏里每次 render 也可重置）

## 8. 常见坑

- **别用编的字段**：`主角.能量` 不对，是 `主角.能量kJ.当前`；回路没有 `damage` 字段，用 `基线账单.计费kJ/一句话效果`
- **别直接改 chat 变量**：必须走 `updateVariablesWith`（不能 `v['渐变带'].能量 = ...` 后丢引用）
- **quote 必须传 ctx**：缺 ctx 会拿默认值，数值全错
- **手操确认只扣费不挂单**：这是用户明确要求，别改
- **状态栏是独立脚本**：没有 `import`、没有扩展的 API，只有酒馆变量 + `window.CircuitEngine`

## 9. 双桌工作台（desk）的流式内嵌契约（v1.5.0 定稿）

`statusbar-desk.html` 是整页应用视觉（GRADIENT ZONE 主题、3400×2200 画布），但要**内联进聊天消息**显示。参考实现：剑与汽水「状态栏电脑」（`E:\deepseek\角色卡\状态栏电脑，其他线用.html`）——它的经验是"**fixed 只用于弹窗与装饰、主体全流式**"。

**铁律（改 desk 布局时遵守）**：

- **`body`/`html` 一条 CSS 都不许写**（尺寸/overflow/背景全归 `#gdesk` 容器；写 body 会把酒馆整页锁死或涂黑）
- 结构：`<div id="gdesk">` 包住 顶部切换条 + HUD 提示 + 侧栏弹窗 + 两个 `.tabletop-viewport`
- 画布视口：`.tabletop-viewport { position:relative; width:100%; height:860px; overflow:hidden }`（高度用户定，宽不锁随消息）；画布表面保持 absolute + 平移/缩放——JS 全是运行时测量（getBoundingClientRect/事件坐标），不依赖视口尺寸，别动
- 侧栏：`.screen-sidebar` 是 fixed 居中弹窗（`translate(-50%,-50%) scale(.92)` → `.open` 显示，`opacity/pointer-events` 控制显隐）；`.sidebar-handle` 是右下角浮动开关；所有 ID 与 JS 逻辑不动
- 未开局兜底：`document.getElementById('gdesk').innerHTML = ...`（**禁止 `document.body.innerHTML`**——会清空整个酒馆页面）
- **曾否决的两个方案别再用**：① 内联布局小修（容器化/absolute 化）当时视觉仍不对；② iframe srcdoc 包裹（墨月工坊模式）被用户明确否决

# 第三部分 · 世界书条目编写参考（系统与数据总览）

> 📦 **已归档**（2026-09 文档三合一）：已并入 docs/具体介绍.md 第三部分。

> 给写世界书条目的 AI：本文档说清「这个跑团系统是怎么跑的、每一刻有哪些数据可以给 EJS 用、
> 世界书条目应该扮演什么角色」——你写出来的条目要用 EJS 把运行状态翻译给正文AI 看，并驱动回合行为。

## 0. 一句话架构

- 扩展 = **开局框架（壳/表格/填表）+ 渐变带（六表施法引擎）**，跑在 SillyTavern 主页面。
- **正文AI 讲故事，脚本算账**：正文 AI 的上下文 = 世界书（你写的条目）＋每楼注入的玩家操作痕迹＋状态栏；
  数据AI 把最新一轮正文翻译成「状态变更包」，脚本核验并结算；结算结果同步成快照给状态栏与世界书 EJS 读。
- 玩家通过**状态栏（悬浮球点开的双桌工作台）**操作：装配回路、手操挂单、送审、补给、删除。

## 1. 回合循环（流程）

```
正文AI（世界书条目 + 楼层痕迹 + 状态栏标记）回复
   │
   ├─ 状态栏 HTML：把最近动作/待扣单提示注入本楼（<StatusPlaceHolderImpl/> 锚点替换）
   │
   ├─ 数据AI：正文 → 状态变更包 JSON（json_schema 强制 → 契约校验，越权=整包打回）
   │     ① 现在剧情时间  ② 本轮使用回路[{回路:id, 次数}]  ③ 剧情数值变更(白名单)
   │     ④ 身体{状态}    ⑤ 战斗中  ⑥ 新增补给(4类+规格)  ⑦ 场景变更  ⑧ 剧情获得(≤1条)
   │
   ├─ settle ⑥ 结算（本地，不回 AI）：
   │     a 扣费/补挂待扣单  b 自由回路计次  …  i 剧情获得→入牌库(待送审)  j 全回路重算过载率/风险
   │
   └─ 快照：chat 变量「渐变带」→ 同步到 message 变量 stat_data.渐变带（最新楼，剥掉 上次结算min）
          → 状态栏双桌/世界书 EJS 从这里读数
```

**玩家操作（不影响本轮正文，影响下一回合结算）**：拖拽装槽（固定槽仅固化）、手操圈选→回合末 ⑥a 统一扣费、
送审槽→法术AI 填参数（通过/驳回/超时/错误均回牌库）、能量/精神补给匣（滑杆按公式耗库存）、删除槽（确认后永久移除）。

**关键分工**：世界书条目 = 「把快照里的运行状态翻译成正文AI 能讲的故事」+「把玩家状态栏操作后的状态变化
写进正文」；数据AI 只认 槽位清单/槽内回路 id，正文AI 也只该用槽内回路。

## 2. 数据在哪（EJS 怎么拿）

世界书条目 = 补充世界观/环境/行为引导 + 把玩家状态栏操作（装配/送审/补给使用/删除）编入叙事，
**不要复述精确数值、不要替脚本写结算**（扣费、恢复、过载计算全归脚本）。

## 6. 建议的世界书条目骨架（EJS）

1. **总览**：世界设定一句话（魔素=未分化能量，五系 = 倾泻/波动/结构/生机/感知，18 分支）

   洗白世界书禁写 AI 运算账目。

## 0. 一句话背景（先理解再写）

- 这是 SillyTavern 上的跑团扩展「渐变带」：**正文 AI 负责讲故事，本地脚本负责算账**。
- 数据AI、法术AI 都是「**翻译器，不是决策器**」：
  - **数据AI**：阅读最近一轮正文 → 翻译成结构化「状态变更包」JSON（脚本再核验并结算）。
  - **法术AI**：审核玩家自创/剧情获得的新回路**物理上是否可行** → 输出「通过/驳回」；剧情获得时还需替它**填参数向量**。
- 输出走 **json_schema 强制结构化**（模型只能按 schema 形状输出，`additionalProperties:false` 禁额外字段）。
- 提示词**分段可编辑**（system/user 段，每段有 `enabled` 开关与 `note` 注释），占位符由代码逐段替换。
- **两个 AI 都不做任何算术、不改任何状态**——一切数值计算归脚本（scheduler/settle/引擎）。

## 1. 数据AI

### 1.1 任务（必须被提示词保留的核心）

读「最近正文」，把它翻译成一份**状态变更包 JSON**：

| 输出字段 | 含义 | 硬约束 |
|---|---|---|
| `现在剧情时间` | 剧情当前时间 | 必须填；格式固定 `2026年11月12日，21：12`（全角逗号）；正文没提时间推进就沿用状态里的时间；比上次结算早=整包打回 |
| `本轮使用回路` | 本回合主角施放了哪些回路 | 数组 `[{回路: id, 次数: int≥1}]`；**id 只能认领「槽位清单」里存在的 id**（认不出来就不报） |
| `剧情数值变更` | 只报**剧情特例**数值变化 | 键白名单：`能量 / 精神 / 能量上限 / 精神上限 / 爆发线 / 持续线`；无特例输出 `{}`。施法消耗、自然恢复、扣费**一律不许报**（脚本算）；`精神上限` 只在突破/觉醒类剧情可提高；`爆发线/持续线` 只能提高（训练/战斗剧情，一次 1~5） |
| `身体` | 身体状态 | `{状态: '正常'\|'轻伤'\|'重伤'\|'过载透支'}` 或 null |
| `战斗中` | 是否处于战斗 | 仅当存在**有敌意的生物**时为 true（追击/被追击、遭遇战都算；**正常切磋/训练对练不算**；无战斗场面输出 null） |
| `新增补给` | 剧情里获得补给 | 只允许 4 类（见词汇表）。**晶体/导液带规格**：晶体 `{名称, 数量, 纯度, 克数}`、导液 `{名称, 数量, 纯度, 容量ml}`（例：魔素晶体，34%纯度，2g；魔素导液，56%纯度，13ml）；**创伤补给** `{名称, 数量}` 严禁填纯度/克数/容量。正文无数字时按「来源场景」三档推断（地摊民用/军用/绝密设施——见提示词第 6 条）；晶体/导液为**库存型**（桌面补给匣滑杆使用，非卡） |
| `场景变更` | 风力/无机物/水体变化 | `{风力档: 0\|40\|70\|95, 可塑无机物kJ, 水体在场}` 或 null |
| `剧情获得` | 剧情明确获得/学会/被授予新法术 | 每回合最多 1 条；只填 `{种类:'fixed'\|'free', 族, 一句话效果, 次数?}`；**不得填参数**（参数由法术AI 送审时填）；`free` 的 `次数` 0~9=初始已用次数，`fixed` 填 10=永久 |

### 1.2 可用的占位符（代码只替换这 4 个；其它 `{{xxx}}` 会原样留着）

| 占位符 | 实际内容 | 说明 |
|---|---|---|
| `{{状态}}` | 脚本 `serialize数据AI(g)` 输出的 JSON：`主角`{能量kJ{当前,上限}、精神点{当前,上限}、爆发线kW、持续线kW、战斗中、身体状态、剧情时间}＋`槽位清单`{固定槽[N]：{序号,类型,id,名称,族,分支,一句话效果}、自由槽[…] }＋`场景`（**补给物品不下发**——数据AI 只负责"新增补给"认领，不需要看到已有库存） | **关键**：槽位清单里每条回路只给 id/名称/族·分支/一句话效果——**参数明细、账单、次数、微调预算一律不下发**，对方 AI 不能、也不该引用这些 |
| `{{场景}}` | 一行文本：`风力：70（劲风）；可塑无机物：1200kJ；水体在场：有` | 风力 0/40/70/95 对应 静风/和风/劲风/风暴 |
| `{{出手单}}` | ~~已删除该段~~：回路 id 已由 `{{状态}}` 的槽位清单提供（固定/自由槽），重复信息不再下发。占位符保留空值兼容旧提示词残留 | 认领用 id 一律看 `{{状态}}` 槽位清单 |
| `{{正文}}` | **分层结构**（脚本 `recentStoryLayered(4)` 生成）：`【前文背景（仅供参考因果，严禁在此提取结算项目）】`＝上一轮及更早（3 轮，其事件已在历史回合结算过）＋`【本轮待结算正文（必须且仅在此范围内提取动作与事件！）】`＝最新一轮（含玩家最新动作 + AI 判定）。每轮前缀 `【玩家】`/`【AI】`，单条截断 3000 字，已剥状态栏标记与代码块 | **唯一信息来源**；配合「事件范围铁律」：结算项目只许从【本轮待结算正文】提取，背景只用于理解意图/因果/时间差——专治跨回合漏判（只给 1 轮丢玩家意图）与历史重复清算（无差别给多轮导致重复扣费） |

### 1.3 输出契约（json_schema，8 字段全部 required）

```jsonc
{
  "现在剧情时间": "2026年11月12日，21：12",
  "本轮使用回路": [{ "回路": "fx-01", "次数": 1 }],
  "剧情数值变更": { "能量": -20 },          // 键仅限白名单
  "身体": { "状态": "轻伤" },               // 或 null
  "战斗中": false,                          // 或 true / null
  "新增补给": [{ "名称": "魔素晶体", "数量": 1, "纯度": 64.2 }],
  "场景变更": { "风力档": 70 },             // 或 null / 空对象
  "剧情获得": [{ "种类": "free", "族": "flow", "一句话效果": "用风压把敌人吹飞", "次数": 3 }]  // 或 []
}
```

### 1.4 脚本后端校验（提示词不能诱导违反，否则整包打回）

1. 顶层字段白名单：上述 8 个键之外出现任何字段 → **整包拒**（防夹带"删除物品/修改参数/修改亲和"）。
2. `剧情数值变更` 出现白名单外键 → **整包拒**。
3. `身体` 只许 `{状态}` 一个键。
4. 时间解析失败 / 时间倒退 → **整包拒**。
5. 回路 id 不在槽位也不在待扣单 → **该条忽略**（不发明账单）。
6. `剧情获得` 超过 1 条 → 只留第一条；一句话效果与已有回路重复 → 忽略。

### 1.5 运行时机

- 开关 `自动结算` 开启时，**每 N 条 AI 回复跑一次**（`频率.数据AI`，默认 N=1，可在设置改）。
- 流程：正文进来 → 调数据AI → 契约校验（失败=打回，本轮不结算，提示可重试）→ `settle()` 结算。

## 2. 法术AI

### 2.1 任务

审核新回路的**物理可行性**（`通过` / `驳回` 二选一）。**审核的是物理，不是亲和**（亲和只影响价格，脚本管）。

同一个提示词模板被 **3 处代码复用**，输出形状有两套（差异在 `规范化回路` 是否含 `参数向量`），写提示词时要覆盖：

| 调用场景 | 谁在调 | `描述` 是什么 | `参数` 是什么 | schema 名 | `规范化回路` 形状 |
|---|---|---|---|---|---|
| **A. 面板「申报入自由库」自创回路** | 双桌 UI（出口 A） | 玩家在构筑台写的作用对象+作用方式原文（≥8 字） | `JSON{族, 参数明细(中文可读), 引擎参考效果}` | `spell_review` | `{名称, 一句话效果, 效果文字稿}`（**无参数向量**；参数由面板滑杆定） |
| **B. 剧情获得回路送审（送审槽/详情页「送审」）** | 双桌 UI（reviewCircuit） | 回路的「一句话效果」 | `参数模板JSON(famKey)`：顶层参数 ctrls + flow 子实体参数 + 默认参数 | `spell_review` | `{名称, 一句话效果, 参数向量}`（**必须含参数向量**，缺省键脚本用默认补齐） |
| C.（bundle 侧同构副本，当前无人调用） | spell-ai.ts | 同 A / 同 B | 同 A / 同 B | `spell_review` / `grant_review` | 同 A / 同 B |

> 因为同一个模板要服务 A、B 两种场景，提示词里对 `规范化回路` 字段的描写应指全两套形状
> （尤其"剧情获得时必须填 `参数向量`"这条必须写清）。

### 2.2 可用的占位符（代码只替换这 5 个）

| 占位符 | 场景 A（自创） | 场景 B（剧情获得） |
|---|---|---|
| `{{描述}}` | 玩家构筑意图原文（如"借由身旁强风流体，塑形高周波风刃切断铁锁"） | 回路的一句话效果 |
| `{{参数}}` | `{ "族": "flow", "参数明细": {…中文标签→值}, "引擎参考效果": "…" }` | `参数模板JSON`：`{族, 说明, 默认参数, 顶层参数:[{key,label,type,opts,min,max,def}], 子实体参数:[…]}`（flow 专属） |
| `{{亲和}}` | `主分支：波动·媒介波；次分支：倾泻·热`（或「无」）——**仅参考，不参与审核** | 同左 |
| `{{场景}}` | `风力：70（劲风）；可塑无机物：1200kJ；水体在场：有` | 同左 |

> 法术AI 只收 4 个占位符：`{{描述}} / {{参数}} / {{亲和}} / {{场景}}`。`{{正文}}`、`{{库索引}}` 均不下发（不查重，AI 只负责物理审核与填参）。

### 2.3 输出契约（两种形状都要能产出）

```jsonc
// A. 自创：通过/驳回
{ "结论": "通过",
  "规范化回路": { "名称": "风刃切", "一句话效果": "借风塑形高周波风刃", "效果文字稿": "…施展描述…" },
  "解释": null }
// 或驳回：
{ "结论": "驳回", "规范化回路": null, "解释": "真空环境没有介质，声波无法传播" }

// B. 剧情获得：通过时必须带 参数向量（键值与引擎参数模板对应）
{ "结论": "通过",
  "规范化回路": { "名称": "风刃切", "一句话效果": "借风塑形高周波风刃",
                   "参数向量": { "mode": 1, "sub": 1, "fmed": 0, "fa": 30, "fv": 58, "br": 90 } },
  "解释": null }
```

### 2.4 提示词必须写进的硬性规则（世界观铁律）

- **五系**按作用方式划分：倾泻（高能热相与电磁·极速杀伤）/ 波动（波与场指挥·借力省耗·共振放大）/ 结构（防御硬化·需要现场有无机物基底）/ 生机（作用于有机体）/ 感知（只读不写）。
- 波动系再分：**实体波**（电磁波/引力波）、**媒介波**（声波/流体/地震——**依赖介质，真空喊话必须驳**）、**场**（电磁场/引力场/核力场）。
- **核力场 = 强/弱相互作用，理论禁区级，能不驳就驳**。
- 名称：**2~7 字纯中文短名**，工业魔导感，杜绝中二浮夸。
- 通过 = 作用对象+作用方式在世界观内可实现、且与参数自洽；驳回要给出**直接给玩家看的通俗解释**（指明缺了什么介质/违背哪条机制）。
- 计费、改状态、算数值 = 它的禁区，全部归脚本。
- ⚠️ **不查重**：`{{库索引}}` 已移除，法术AI 看不到已有回路列表，不要写"重名需驳回/改名"类规则（无输入可依）。

### 2.5 失败降级

- 法术AI 调用失败/超时/未启用：bundle 侧降级引擎 `localJudge` 本地兜底；双桌 UI 侧 15 秒超时令牌丢弃迟到响应，**通过/驳回/超时/错误都清送审槽、牌自动回牌库**。
- 通过后脚本会 `钳制参数()`：seg 下标 / range 最小最大值钳制到引擎合法范围、删非法键——所以提示词让 AI 填参数时**不用追求完美值，缺省键可留省**。

## 3. 流程全景

```
酒馆正文 AI 回复
  │
  ├─ ✨ 数据AI（每 N 条 AI 回复一次）
  │    正文{{正文}} + 状态{{状态}} + 场景{{场景}}（回路 id 认领看 {{状态}} 槽位清单）
  │      → json_schema 强制 → 变更包 JSON
  │      → contract.ts 契约校验（越权=整包打回）
  │      → settle.ts 结算（a 补挂待扣单 / b 计次 / … / i 剧情获得入牌库[待送审] / j 重算过载）
  │
  └─ ✨ 法术AI（两种入口，共用一份提示词）
       A. 玩家在自由施法桌调好参数 →「申报入自由库」→ 通过=入自由库(type:free)
       B. 剧情获得的「待送审」牌 → 拖入送审槽 →「送审」→
            通过 = 填参数向量 + 审核状态→'已通过'，可装自由槽/施放
            驳回 = 回牌库，可再送
```

**两个 AI 的交界**：数据AI 报的「剧情获得」只给出 种类/族/一句话效果（参数占位），
玩家手动拖进送审槽 → 法术AI 填参数 → 才从 `待送审` 转 `已通过`。
